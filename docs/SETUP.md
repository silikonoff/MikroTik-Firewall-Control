# Настройка MikroTik для MFC

[← README](../README.md) · [Установка](INSTALL.md) · [Диагностика](FAQ.md)

Администратор готовит роутер один раз, затем оператор работает с карточками групп. Нужна RouterOS 7. MFC не создаёт правила, пользователей и сертификаты автоматически.

## 1. Включите нужную службу

В WinBox/WebFig откройте **IP → Services**. Выберите тот же режим, который затем укажете в MFC.

| Режим в MFC | Служба RouterOS | Порт по умолчанию | Права пользователя |
|---|---|---:|---|
| REST / HTTPS | `www-ssl` | 443 | `read, write, api, rest-api` |
| REST / HTTP | `www` | 80 | `read, write, api, rest-api` |
| Обычный API | `api` | 8728 | `read, write, api` |
| API-SSL | `api-ssl` | 8729 | `read, write, api` |

Порт можно изменить, но он должен совпадать на телефоне и роутере. Для обычного API веб-службы `www`/`www-ssl` не требуются. HTTP REST доступен с RouterOS 7.9. В версиях с разделом **Web Server** дополнительно разрешите REST для выбранного протокола.

HTTPS/API-SSL требуют назначенного службе сертификата: действующий срок, SAN для выбранного IP/DNS и доверенный Android CA. Для собственного CA установите его публичный сертификат в доверенные CA телефона. Проверка TLS приложением не отключается.

HTTP и API без TLS передают пароль открыто. Ограничьте доступ к службе доверенными LAN/VPN-подсетями через Available From и firewall; не открывайте управление всему интернету.

## 2. Создайте отдельного пользователя

**System → Users → Groups:** создайте группу с правами из таблицы. В **Users** создайте пользователя этой группы с собственным паролем. При ограничении Address включите адрес/подсеть, с которой действительно приходит телефон, в том числе через VPN.

## 3. Пометьте нужные правила

В комментариях проверенных firewall-правил используйте маску **`APP_STOP_*`**. Звёздочку замените именем группы:

| Комментарий | Что появится в MFC |
|---|---|
| `APP_STOP_VPN` у нескольких правил | Одна карточка **VPN**, управляющая этими правилами |
| `APP_STOP_GUEST` у других правил | Отдельная карточка **GUEST** |
| `APP_STOP_VPN \| Остановка VPN-трафика` | Та же группа **VPN**, текст после разделителя — описание |

- Имя — до 64 символов: латинские буквы, цифры, `_` и `-`; первый символ — буква или цифра. Регистр не важен.
- `APP_STOP_*` со звёздочкой и `APP_STOP_` без имени — не готовые комментарии, группа по ним не появится.
- Описание отделяется символом `|`. Оно показывается на карточке, если одинаково у всех правил группы.
- Одинаковое имя объединяет правила даже из разных IPv4-таблиц **Filter/NAT/Mangle/Raw**. Для раздельного управления используйте разные имена.

Назначение правил проверяет администратор: action, chain, адреса/направления, порядок, FastTrack и существующие соединения. Не добавляйте в рабочую группу правила, которые могут перекрыть управление роутером. MFC меняет только состояние включения; он не меняет параметры правила и не подтверждает фактическую блокировку трафика.

## 4. Добавьте подключение на телефоне

**MFC → ⋮ → Настройки администратора → `0000` → Добавить подключение**. Смените начальный PIN в разделе «Доступ администратора».

Укажите название объекта для оператора, IP/DNS без схемы и порта, учётную запись, интерфейс REST/API, протокол и порт. Затем выберите маршрут:

| Сценарий | Режим MFC |
|---|---|
| Телефон в локальном Wi-Fi роутера | Wi-Fi напрямую |
| Доступ через готовый VPN-туннель | Системная сеть / VPN |
| Телефон подключён через USB/OTG-LAN | Ethernet |

Сохраните профиль и выберите его рабочим в списке подключений. Новые профили по умолчанию выбирают прямой Wi-Fi; старые сохраняют прежние параметры. При сохранении HTTP/API без TLS подтвердите предупреждение о передаче без шифрования.

Для локальной LAN интернет не нужен; нужны IP-связность и поддержка USB-адаптера, если выбран Ethernet. Прямой Wi-Fi обходит VPN намеренно. Системный режим следует выбранной Android сети, которая может включать мобильную; при обязательном VPN используйте блокировку соединений без VPN в Android. Создание VPN-туннеля в эту инструкцию не входит.

## 5. Проверьте перед передачей оператору

На безопасной тестовой группе: дождитесь связи → включите её с основного экрана → независимо проверьте состояние правил на MikroTik → войдите в админку → «Выключить правила / восстановить трафик» → выберите группу → снова проверьте роутер.

Затем проверьте фактическое прохождение нужного трафика и потерю связи. Полный [чек-лист](TESTING.md), [памятка оператору](OPERATOR.md), [разбор ошибок](FAQ.md).

Официальные справочники: [API](https://manual.mikrotik.com/docs/developer-guides/api/), [REST](https://manual.mikrotik.com/docs/developer-guides/rest-api/).
