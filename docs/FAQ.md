# Вопросы и диагностика

[← README](../README.md) · [Установка](INSTALL.md) · [Настройка](SETUP.md)

## Быстро найти причину

Технические сведения: **⋮ → Настройки администратора → Диагностика подключения**. Выберите правильный рабочий роутер перед проверкой.

| Что произошло | Что проверить |
|---|---|
| Нет соединения / Failed to connect | IP/DNS, выбранный маршрут, доступность службы и её порта, firewall роутера |
| REST 401 / API: вход отклонён | Логин, пароль, права группы пользователя и разрешённые адреса его входа |
| REST 403 / команда API отклонена | Разрешение REST для выбранного протокола и права `read`, `write`, `api`; для REST также `rest-api` |
| Ошибка TLS | Назначен ли сертификат службе, доверяет ли телефон CA, совпадает ли SAN с IP/DNS; срок и время телефона |
| Связь есть, групп нет | Комментарии правил: маска `APP_STOP_*`, имя группы и разделитель `\|` перед описанием |
| Не получается включить группу | Есть ли динамические или invalid-правила; не изменился ли состав после показа карточки |
| Операция не подтверждена | Перечитайте состояние: часть правил могла измениться. Автоматического отката нет |
| Android не устанавливает обновление | Версия Android, целостность APK, свободное место и совпадение подписи с установленной сборкой |

## Нужен ли интернет?

Для связи с роутером в локальной сети — нет. Нужны рабочее подключение телефона и IP-доступ к роутеру. Удалённый доступ через VPN требует готового работающего туннеля.

## Что выбрать: REST или обычный API?

Используйте интерфейс, который настроил администратор. REST работает через `www`/`www-ssl`; обычный API — через `api`/`api-ssl` и не требует веб-службы. Права и порты перечислены в [SETUP](SETUP.md). Приложение не меняет протокол автоматически.

## Почему при VPN нельзя выбрать «Wi-Fi напрямую»?

Этот режим намеренно обращается к роутеру через Wi-Fi, обходя VPN. Для туннеля выберите **«Системная сеть / VPN»**. В нём Android выбирает активную сеть; после потери VPN следующая операция может использовать другой маршрут. Для обязательного туннеля нужна системная блокировка соединений без VPN.

## Я ввёл `APP_STOP_*`, но группа не появилась

`*` — обозначение места для имени, а не символ для комментария. Напишите, например, **`APP_STOP_VPN`**. Имя должно начинаться с латинской буквы или цифры; допустимы латинские буквы, цифры, `_` и `-`, до 64 символов. [Примеры](SETUP.md#3-пометьте-нужные-правила).

## Можно ли объединить Filter и NAT в одну группу?

Да. Одинаковое имя после `APP_STOP_` объединяет правила из всех четырёх поддерживаемых IPv4-таблиц: Filter, NAT, Mangle, Raw. Чтобы управлять ими отдельно, задайте разные имена групп.

## Правила включились, а трафик продолжает идти

Приложение подтверждает состояние правил, а не результат измерения трафика. Администратору нужно проверить action, chain, порядок, адреса/направления, FastTrack и существующие соединения. Включение NAT- или разрешающего правила само по себе не означает блокировку.

## Почему нельзя восстановить трафик с главного экрана?

Так разделены роли: оператор включает правила остановки, администратор выключает их. Восстановление: **⋮ → Настройки администратора → PIN → Выключить правила / восстановить трафик → группа**.

## PIN `0000` не подходит / PIN забыт

`0000` действует только как начальное значение до смены PIN. Обновление приложения не возвращает его к `0000`. Встроенного восстановления PIN нет; обратитесь к администратору, который его установил. Очистка данных Android удаляет и локальные подключения, и PIN. Ошибка чтения файла PIN не сбрасывает защиту автоматически.

## Что делать при конфликте подписи APK?

Проверьте, не установлена ли сборка из Actions или собственной сборочной среды. Она может иметь другой ключ, чем APK из Releases. Android не разрешает обновлять приложение несовместимой подписью. Для сохранения данных используйте обновление, подписанное тем же ключом; удаление приложения приведёт к потере его локальных настроек.

## Ошибка осталась

Создайте [Issue об ошибке](https://github.com/silikonoff/MikroTik-Firewall-Control/issues/new?template=bug_report.yml). Укажите версии MFC/Android/RouterOS, протокол, маршрут, шаги и ожидаемый результат. Скройте адреса, имена объектов, логины и секреты на снимках. Об уязвимости сообщайте [приватно](https://github.com/silikonoff/MikroTik-Firewall-Control/security/advisories/new).
