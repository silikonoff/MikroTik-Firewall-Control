# Участие в разработке

Исправления и предложения приветствуются. Для заметного изменения сначала откройте Issue с проблемой и ожидаемым поведением. Небольшое исправление можно предложить Pull Request сразу.

1. Сделайте fork и рабочую ветку.
2. Сохраните текущую Kotlin/Activity-архитектуру и совместимость профилей.
3. Для сетевых изменений проверьте маршруты, TLS, ошибки/частичный результат и отсутствие повторов записи. Не добавляйте скрытый fallback или trust-all.
4. Для нового поведения добавьте осмысленные тесты. Запустите unit tests, lint и assembleDebug по [BUILD.md](docs/BUILD.md).
5. Опишите, что реально проверено: JVM, эмулятор, смартфон, модель адаптера, версия RouterOS. Не выдавайте имитацию за аппаратную проверку.

Не присылайте секреты, реальные дампы сети, приватные сертификаты или ключи подписи. В примерах используйте тестовые данные. Общайтесь уважительно; обсуждайте поведение и код.

Для правок только документации проверьте ссылки, примеры, точные названия кнопок и соответствие коду. Повторная Android-сборка для такой правки не нужна. Избегайте терминов без объяснения: инструкцией пользуются и оператор, и администратор. [Правила общения](CODE_OF_CONDUCT.md).

## Что нуждается в проверке

Особенно полезны результаты по [аппаратному чек-листу](docs/TESTING.md): API/API-SSL, USB-адаптеры, VPN/потеря сети и ограничения администратора при сворачивании/повороте экрана. Указывайте конкретную конфигурацию и фактический результат; общий комментарий «всё работает» не подтверждает все режимы.

## Подготовка нового релиза

- Согласовать `versionName`/`versionCode`, имена APK в build-скриптах и Actions.
- Обновить ссылки APK/SHA256/релиза в README и INSTALL, CHANGELOG и описание статуса проверки.
- Пройти unit tests/lint/build и применимые аппаратные проверки; подписать APK постоянным ключом, отдельно от временной CI-подписи.
- Проверить package/label/version/signature, сохранить SHA256, загрузить APK и сумму в Releases.
- Проверить доступность ссылок и контрольную сумму загруженного вложения. Предварительный статус снимать только после соответствующей приёмки.
